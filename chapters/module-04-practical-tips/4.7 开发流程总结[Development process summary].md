# 开发流程总结 Development process summary

**核心思想：构建和分析来回切换，分析的重要性和构建相当——很多团队栽在花太多时间写代码，太少时间想清楚下一步该改哪里。**

本模块前六节讲了评估、错误分析、组件级评估、改进方法、成本与延迟优化这些具体工具。这一节把它们串起来，看清完整的开发流程是什么样的。

---

## 一、两大活动：构建与分析

开发 Agent 工作流时，主要精力在两件事之间来回切换：

| 活动 | 做什么 |
|---|---|
| **构建 (Building)** | 写软件和代码来改进系统 |
| **分析 (Analyzing)** | 决定下一步把构建精力集中在哪里 |

分析的重要性和构建相当。很多人觉得"写代码"才是干活，"想问题"不算——但在 Agent 系统里，不分析就盲目改代码，改半天发现改错了地方，比不改还浪费。

---

## 二、四个迭代阶段

一个 Agent 系统从初始原型到成熟，分析工作的严谨程度逐步提高，通常经历四个阶段：

| 阶段 | 描述 | 分析工作 |
|---|---|---|
| **1. 快速原型** | 快速构建一个端到端系统（"先做个垃圾出来"） | 手动检查最终输出，通读追踪 (Traces)，凭直觉找出性能不佳的组件 |
| **2. 初步评估** | 系统开始成熟，超越纯手动观察 | 构建初步的端到端评估 (E2E Evals)，用 10-20 例小数据集算整体性能指标 |
| **3. 严谨分析** | 系统需要更精确的改进方向 | 做错误分析 (Error Analysis)，统计和量化各组件导致次优输出的频率，做集中决策 |
| **4. 高效调优** | 系统进一步成熟，需要组件级别高效改进 | 构建组件级评估 (Component-Level Evals)，高效调优单个组件 |

四个阶段对应本模块的前六节：

```
阶段 1 快速原型     → 4.1 评估（从 10-20 例起步）
阶段 2 初步评估     → 4.1 评估（2×2 矩阵选方法）
阶段 3 严谨分析     → 4.2 错误分析 + 4.3 更多错误分析示例
阶段 4 高效调优     → 4.4 组件级评估 + 4.5 改进方法 + 4.6 成本与延迟优化
```

---

## 三、非线性过程

开发没有线性路径（做完阶段 1 做阶段 2 做阶段 3 做阶段 4），实际是在调整系统、错误分析、改进组件、调整评估之间反复横跳。

一个典型的迭代循环：

1. 改了某个组件（构建）
2. 跑端到端评估看整体有没有变好（分析）
3. 发现某个案例变差了，做错误分析定位原因（分析）
4. 定位到是另一个组件的问题，建组件级评估（分析）
5. 调参优化该组件（构建）
6. 回到端到端评估验证（分析）
7. 发现新问题，循环继续

```
构建 → 分析 → 构建 → 分析 → 构建 → 分析 ...
 ↑                              |
 └──────────────────────────────┘
```

每一轮循环都让系统更接近成熟。关键是在每一轮里都先分析再构建，别跳过分析直接改代码。

---

## 四、常见误区：构建太多，分析太少

经验不足的团队最容易栽在这里——花太多时间在构建上，太少时间在分析上。

典型表现：
- 系统输出不好，立刻开始改 Prompt，改了十几个版本看效果
- 改了半天发现真正的瓶颈在搜索组件，Prompt 改的方向全错了
- 或者换了三个模型都不行，最后做错误分析才发现是数据库脏数据

本模块反复强调的就是：**先分析定位，再构建改进。** 错误分析花的时间，比盲目改代码省下来的时间多得多。

---

## 五、工具与定制评估

市面上有很多工具可以帮助监控追踪、记录运行时、计算成本——LangSmith、Langfuse、SkyWalking、Arize Phoenix 等等。团队可以尽情用这些前人造的轮子，不必自己从零搭监控基础设施。

但 Agent 工作流高度定制化，通用工具覆盖不到所有场景。团队最终仍需要自行构建许多**定制化的评估**，以准确捕获系统特有的问题。比如：
- 发票提取系统的"到期日 vs 发票日期混淆"评估
- 客服 Agent 的"SQL 查询正确性"评估
- 研究 Agent 的"黄金标准网页召回率"评估

这些评估跟具体业务强绑定，通用工具给不了，只能自己建。本模块讲的方法论就是教你怎么建这些定制评估。

## 六、Module 4 完整闭环

把前六节串起来，一个成熟的 Agent 开发流程形成完整闭环：

```
4.1 评估 Evals
  │  先建端到端评估，知道整体表现
  ▼
4.2-4.3 错误分析 Error Analysis
  │  拆开 Trace 定位哪个组件出错最多
  ▼
4.4 组件级评估 Component-Level Evals
  │  为问题组件单独建评估，快速迭代
  ▼
4.5 改进方法 How to address problems
  │  调参数/改提示词/换模型/任务分解/微调
  ▼
4.6 成本与延迟优化 Latency & Cost
  │  质量达标后优化速度和成本
  ▼
回到 4.1 端到端评估验证整体提升
```

这个闭环对应四阶段迭代：快速原型（4.1）→ 初步评估（4.1）→ 严谨分析（4.2-4.3）→ 高效调优（4.4-4.6）。每一轮循环都让系统更接近成熟。

Andrew Ng 在课程最后说：能否进行严格、有纪律的评估，是区分"做得好"与"做得差"的 Agent 开发者的最大预测因素。这套系统化的开发流程——评估、错误分析、改进——就是支撑复杂 Agent 系统的核心能力。

---

**总结**

- 开发两大活动：构建（写代码）和分析（定方向），两者来回切换，分析的重要性不亚于构建
- 四阶段迭代：快速原型 → 初步评估 → 严谨分析 → 高效调优，分析工作逐步严谨
- 开发是非线性过程，在调整系统、错误分析、改进组件、调整评估之间反复横跳
- 常见误区：构建太多分析太少。先分析定位再构建改进，比盲目改代码高效得多
- 通用工具（LangSmith/Langfuse/SkyWalking 等）负责监控基础设施，定制评估负责业务特有问题
- 完整闭环：评估 → 错误分析 → 组件级评估 → 改进 → 成本延迟优化 → 回到评估验证

下一模块会讲更高级的设计模式——Planning（规划）和 Multi-Agent（多智能体协作），让 Agent 处理更复杂的自主任务。
