# 评估与边界 [Evaluation and Bounds]

**核心思想：反思值不值得用要靠数据说话；循环要能停下来，否则质量收益会被失控的迭代成本吃掉。**

---

## 七、评估反思的影响：用数据说话 (Evaluating Reflection)

反思带来质量收益，也带来调用成本、耗时和费用。它到底值不值得保留，要靠评估。

### 把两个版本放到同一套标准下

先建立直接生成的基线（Baseline），再增加反思步骤，在相同任务上比较 [1]。

| 比较条件 | 实施建议 |
|---|---|
| 问题与资料 | 使用相同问题、业务口径与数据快照 |
| 模型与提示 | 固定并记录版本，说明增加了哪些步骤 |
| 验收标准 | 使用相同的答案规则或评分表 |
| 运行条件 | 记录超时、重试和工具异常 |
| 资源消耗 | 同时记录调用、费用和端到端耗时 |

### SQL：核对答案，也追踪错误

课程用数据查询说明评估方法。对「哪种颜色的产品总销量最高」这类需求 [1]：

| 版本 | 处理过程 |
|---|---|
| 无反思 | 问题 → SQL V1 → 执行 → 最终回答 |
| 有反思 | 问题 → SQL V1 → 评审并修订 → 执行 → 最终回答 |

正确率反映整体变化，逐题配对结果说明变化来自哪里：

| 基线结果 | 反思后结果 | 记录含义 |
|---|---|---|
| 错误 | 正确 | 修复成功 |
| 正确 | 错误 | 修订退化 |
| 正确 | 正确 | 保持正确 |
| 错误 | 错误 | 问题仍待解决 |

课程中的 SQL 示例从 87% 提升到 95%，绝对提升 8 个百分点 [1]。这个数字用于说明评估方法；方案收益和对外承诺采用自身业务样本的验证结果。

### 模型当裁判，裁判也要校验

模型裁判（LLM-as-a-Judge）可以承担批量初评，评分是否稳定、是否符合人工标准同样需要检查 [6]。

#### 位置偏差：顺序影响判断

成对比较时，模型可能受候选结果的位置影响。可采用匿名标识、交换顺序复评，并保留平局或待确认结果 [6]。

#### 自偏好偏差：更认可自己的输出

模型倾向于更认可自身或同系列模型的输出。Pombal 等人在 IFEval、LiveCodeBench 和 HealthBench 等设置下发现，即使逐条使用评分标准，这类偏差仍可能存在；多个裁判组合有所缓解，但仍有残余 [5]。

| 风险或现象 | 检查与处理 |
|---|---|
| 交换候选顺序后判断改变 | 匿名展示，交换顺序复评，记录平局与分歧 |
| 同样结果多次评分差异较大 | 细化标准，检查重复评分稳定性 |
| 模型倾向于认可自身输出 | 独立样本校准，增加程序或人工抽查 |
| 模型高分与业务判断不一致 | 用业务认可的正反例校准评分表 |

用模型裁判做批量初评可以，但分数要经过专家样本校准才能对外展示。任务内的修改建议和最终的交付确认要分开，前者可以自动，后者保留独立校验或人工把关。

### 分三步决定是否采用

第一步，看有没有改善：用有代表性的业务样本比较质量，记录修复、退化和未解决问题。第二步，看值不值得投入：核算费用、耗时和人工工作量。第三步，看实际运行是否稳定：进入小范围试用后，观察高峰请求、数据异常、工具超时和人工接管 [1]。

| 维度 | 可记录的指标 |
|---|---|
| 质量 | 正确率、验收通过率、评分分布 |
| 稳定性 | 失败率、重复运行波动、修订退化 |
| 时延 | 端到端耗时，样本充分时补充分位数 |
| 费用 | 单次任务的模型、工具、重试与评估开销 |
| 人工投入 | 审核、接管与返工时间 |

## 八、结束与验收：给循环设边界 (Stopping Conditions)

反思本质是一个循环。循环要能停下来，否则质量收益会被失控的迭代成本吃掉。

| 触发条件 | 建议处理 |
|---|---|
| 已满足验收标准 | 保存验证记录并结束 |
| 新版本改善了已定义指标 | 保留修订版，按预算决定后续步骤 |
| 新版本出现退化 | 保留已有较好版本，记录回退原因 |
| 连续出现同类问题 | 暂停自动修订，检查资料和检查规则 |
| 达到次数、时间或成本预算 | 返回当前状态和待解决项 |
| 事实缺失或授权边界待确认 | 转人工确认后继续 |

版本保留依据规则检查、测试和人工评审结果作出选择；保留每次变更和验证记录，有助于排查反复修改的问题。

---

**总结**

1. **反思方案的采用取决于可验证的质量收益与成本、延迟之间的权衡**，先看有没有改善，再核算投入，最后验证运行稳定。
2. **模型裁判存在位置偏差和自偏好**，评分表需要校准，分数经校准后才能对外展示。
3. **停止条件、版本保留和人工接管共同约束迭代范围**，循环不设边界会被失控的迭代成本吃掉收益。
